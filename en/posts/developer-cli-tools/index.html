Beyond Feishu CLI: Developer Command-Line Tools You May Not Know

Eva·2026.05.06·12 min read

 

How many tools have quietly moved their core capabilities into the command line?

CLI tools once seemed mostly confined to programmers' local toolboxes: finding files, running scripts, sending requests, and deploying services. Now their reach is expanding rapidly. Feishu connects messaging, calendars, documents, and agent workflows through the command line; GitHub manages PRs and issues through a CLI; cloud providers expose servers, databases, and storage; and AI tools are also entering the terminal as CLIs.

That raises an interesting question: beyond Feishu CLI, which potentially unfamiliar CLI tools have already become important?

Viewed more broadly, a CLI is no longer merely a place for programmers to type commands. It is a common interface for modern software engineering, connecting collaboration platforms, cloud services, AI models, containers, CI/CD, security scanning, and productivity tools. Its value grows further in the AI agent era: to accomplish real engineering tasks, agents need stable, automatable, composable command-line tools.

awesome-cli (https://github.com/Eva-Dengyh/awesome-cli) collects high-quality CLIs for enterprise collaboration, cloud services, AI/LLMs, file processing, network debugging, containers and K8s, IaC, security scanning, and developer productivity—all official tools or projects with over 10,000 GitHub stars. It helps developers and AI agents perform engineering tasks through the command line. More than a list, it maps a modern engineering-tool ecosystem for developers and agents.

The CLI as a common interface for modern engineering

Command-line tools have long been considered developers' productivity power tools. Whether searching files, processing JSON, managing cloud resources, deploying applications, or scanning security risks, their lightweight, composable, scriptable nature makes them one of engineering's most stable infrastructure layers.

As AI agents enter software engineering workflows, that value is growing again.

For developers, the CLI provides efficient access to operating systems and engineering environments. For AI agents, it is an execution interface to real toolchains. An agent limited to generating suggestions has limited capability. With access to CLIs for GitHub, cloud platforms, CI/CD, databases, security scanning, and file processing, it can participate in the complete engineering process: requirements analysis, code changes, testing, deployment, and troubleshooting.

Generality is a major reason CLIs endure.

Graphical interfaces suit human browsing and clicking; APIs suit integration between programs. CLIs sit between them: people can use them directly, while scripts, CI/CD systems, and AI agents can invoke them too. They naturally support automation, provide clear inputs and outputs, compose easily, and lend themselves to standardized workflows.

Developers can use GitHub CLI to inspect issues, create pull requests, and trigger workflows; AWS CLI, Alibaba Cloud CLI, and Tencent Cloud CLI to manage cloud resources; Terraform or OpenTofu to declare and change infrastructure; and Trivy, Gitleaks, and TruffleHog to scan images, code, and leaked secrets. Operations once scattered across platforms and consoles share a single command-line interface.

That common interface becomes even more important with AI agents. Rather than understanding every platform's complex GUI, an agent needs to understand commands, parameters, outputs, and errors to connect tools into more sophisticated engineering workflows.

Collaboration CLIs: Bringing engineering communication into automation

Modern software development begins with collaboration. Code, requirements, defects, reviews, releases, and documentation are often spread across multiple platforms.

GitHub CLI and GitLab CLI are leading examples among international collaboration platforms. They let developers manage pull requests, merge requests, issues, pipelines, and workflows directly in the terminal. Jira CLI extends this to task management and defect tracking, reducing browser switching.

In Chinese enterprises, platforms such as Feishu, DingTalk, and WeCom are also offering or exploring CLI capabilities. Messaging, calendars, documents, approvals, meetings, and organizational collaboration can therefore enter automated workflows. For AI agents, these tools are particularly important because they connect to the team's collaboration itself, beyond its repositories.

An engineering agent might modify code, create a branch from an issue, implement the change, submit a PR, produce release notes, and synchronize the result to the team's collaboration platform. Collaboration CLIs underpin that process.

Cloud-service CLIs: From console clicks to orchestrated infrastructure

Cloud services are among the most mature areas of the CLI ecosystem.

AWS CLI, Alibaba Cloud CLI, Tencent Cloud CLI, Huawei Cloud KooCLI, JD Cloud CLI, Volcengine CLI, and others cover compute, storage, networking, databases, permissions, monitoring, and many other cloud capabilities. Operations once performed in consoles can now run from the command line and become scripts, CI/CD steps, or agent workflows.

The change is clear: cloud resource management moves from manual clicking to an engineering process that is recorded, reproducible, and auditable.

For enterprises, CLI-based cloud management reduces repetitive work and human error while integrating with permissions, release, and security systems. For agents, cloud CLIs provide direct infrastructure access. Naturally, access control, audit logs, and security boundaries become more important as well.

AI CLIs: Large models enter the terminal

AI tools themselves are becoming command-line tools.

Ollama lets developers run large language models locally for private deployments, offline use, or low latency. Simon Willison's llm tool provides a general LLM command-line interface, bringing different models into terminal workflows. Chinese providers are also releasing AI CLIs for developers and agents, including Volcengine veCLI and Tencent AI CLI.

These tools turn model invocation from something confined to a web chat or application feature into a composable command-line capability.

For example, developers can pipe logs to a model to summarize failures, send code diffs for review suggestions, or extract summaries from document excerpts. Once available through a CLI, AI can combine with traditional tools such as jq, rg, fzf, git, curl, kubectl to create new development practices.

File-processing CLIs: The foundation of developer productivity

While cloud and collaboration CLIs connect external systems, file-processing tools connect the local engineering environment developers face every day.

ripgrep, fd, fzf, bat, jq, yq and similar tools are fundamental components of modern command-line workflows. Their tasks seem simple: searching text, finding files, previewing content, and processing JSON or YAML. Yet these are prerequisites for understanding and working with large codebases.

They matter equally to AI agents. Agents need to search code, locate configuration, read logs, parse structured data, and select relevant information. High-quality file CLIs help agents understand project context faster and more accurately, reducing unnecessary scans and mistaken conclusions.

File-processing tools improve both human productivity and agents' ability to execute engineering work.

Network and API CLIs: The front line of service debugging

Network and API debugging are frequent tasks in backend development, microservices, and platform engineering.

hurl can describe and test HTTP requests in plain-text files, making API verification suitable for version control.grpcurl provides a curl-like debugging experience for gRPC services.mitmproxy supports HTTPS proxying and traffic analysis to investigate requests, responses, authentication, and data-transfer problems.

Together these tools form the front line of service debugging. Compared with graphical API tools, CLIs fit more easily into automated tests, continuous integration, and troubleshooting scripts.

For AI agents, network and API CLIs allow actual requests, response observation, and hypothesis testing, beyond merely inferring behavior from code. They are essential for engineering agents to evolve from coding assistants into debugging assistants.

Containers, Kubernetes, and CI/CD CLIs: The core of modern delivery

Modern application delivery depends heavily on containers, Kubernetes, and CI/CD, fields built almost naturally around CLIs.

kubectl is the de facto interface to Kubernetes; helm packages and releases Kubernetes applications; kubectx helps developers switch quickly between cluster contexts and namespaces; dive analyzes Docker image layers to optimize image size and investigate build issues.

In CI/CD, act runs GitHub Actions locally; ArgoCD supports GitOps continuous delivery; Dagger and Earthly provide more programmable, reproducible builds and pipelines.

These tools transform delivery from manual steps on one machine into declarative, executable, verifiable pipelines. Agents invoking these CLIs can analyze build failures, repair pipelines, inspect deployment state, and even perform prerelease verification under controlled permissions.

IaC and security CLIs: Addressing risk earlier

Infrastructure as code and security scanning are two particularly automation-friendly areas of the CLI ecosystem.

Terraform and OpenTofu let infrastructure changes be managed, reviewed, and rolled back like code. Infracost estimates cloud costs before changes, exposing their impact during pull-request review. Trivy, Gitleaks, and TruffleHog cover container security, dependency risk, code scanning, and leaked-secret detection.

Their shared value is moving risk control earlier.

Many security and cost problems used to surface only after release. They can now be detected automatically when committing code, building images, creating PRs, or before deployment. Enterprises gain more consistent delivery quality; agents can verify risks during execution as well as completing tasks.

Productivity and shell enhancements: Modernizing the command line

The CLI ecosystem cares about everyday developer experience as well as large systems.

just and task offer modern alternatives to traditional Makefile task execution; hyperfine benchmarks commands; navi and tldr reduce the burden of remembering complex commands; direnv automatically loads project-level environment variables; zoxide, atuin, eza, delta improve directory navigation, history search, file listings, and git diff respectively.

These seemingly scattered tools point to one trend: the command line is evolving from a basic black-and-white entry point into a modern, customizable, intelligent development environment.

Combined, they turn the terminal into an engineering workbench for search, navigation, debugging, analysis, deployment, and collaboration, beyond simply executing commands.

The CLI will become more valuable in the AI agent era

For human developers, the CLI's value is efficiency. For AI agents, it is the ability to execute.

Agents must operate real engineering systems beyond offering textual advice. They need to read files, search code, call APIs, run tests, manage issues, check CI, scan risks, deploy services, and synchronize collaboration platforms. The best interface is often a CLI already proven throughout engineering practice, rather than a webpage or an isolated API.

An important future criterion for whether a tool suits AI agents may therefore be whether it offers a stable, clear, automatable command-line interface.

For vendors, a CLI may become a critical gateway for agents into their ecosystem, beyond an advanced-user accessory. For development teams, organizing and standardizing internal CLIs will also underpin agent-native engineering systems.

Finally

awesome-cli (https://github.com/Eva-Dengyh/awesome-cli) maps the modern developer CLI ecosystem, rather than merely collecting tools.

From enterprise collaboration to cloud services, AI to file processing, network debugging to Kubernetes, CI/CD to security scanning, and shell enhancements, CLIs now span almost every stage of software engineering. They improve individual productivity, support team automation, and will increasingly bridge agents with real engineering systems.

Future engineering will happen beyond IDEs and web consoles. More capabilities will settle into command-line tools shared by people, scripts, pipelines, and AI agents.

Understanding the CLI ecosystem means understanding the automation foundation of modern software engineering.
