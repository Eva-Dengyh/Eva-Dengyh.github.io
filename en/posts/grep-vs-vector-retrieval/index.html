Why Does Simple grep Outperform Complex Vector Retrieval on Multi-hop Reasoning Tasks?

Eva·2026.05.13·13 min read

 

Where the Question Comes From

Have you ever wondered why AI retrieval systems always give you top-k results before they begin reasoning?

The design seems sensible: first filter with BM25 or a vector database, retrieve the most relevant documents, and then let a large model interpret them. It is fast, inexpensive, and easy to implement.

But here is the problem:What if useful evidence is filtered out in the very first step?

Traditional retrieval systems, whether sparse or dense, essentially perform "compression": they compress the entire corpus into a fixed top-k interface. That interface works for simple question answering but becomes a bottleneck for agent tasks requiring multistep reasoning:

  • Precise lexical constraints, such as "must contain both A and B," are difficult to express
  • Combining sparse clues, such as "a report from 2024," requires multiple queries
  • Inspecting local context, such as "what are the ten lines around this keyword?", is simply impossible
  • Multistep hypothesis refinement, such as "find the entity first, then the relationship," is broken into independent retrieval steps

Worse still, once evidence is filtered out at the first step, no amount of subsequent reasoning can recover it.

This is the central problem the paper addresses.

Their Approach: Interact Directly with the Corpus

The paper proposes a seemingly counterintuitive approach:Direct Corpus Interaction (DCI) — Let agents search the raw corpus directly using terminal tools—grep, file reads, shell commands, and lightweight scripts—with no embedding model, vector index, or retrieval API.

Sounds primitive? The results are remarkable.


This chart shows a Pareto frontier analysis: cost (API call count) on the horizontal axis, accuracy on the vertical axis. We can see:

  • The DCI-Agent family (red) clearly outperforms all traditional retrieval methods (blue)
  • Even the lightest DCI-Agent-Lite achieves higher accuracy at lower cost

The Core Idea

Traditional retrieval pushes "semantic understanding" down to the indexing layer—embedding model plus vector database—and gives the agent a compressed interface.

DCI reverses this:It brings semantic understanding back to the LLM layer and gives the agent a high-resolution raw interface.

Specifically, agents can:

  • Use grep 'foo' file | grep 'bar' to enforce multiple lexical constraints
  • Use find . | grep 'report' | grep '2024' to combine weak clues
  • Use grep -n 'keyword' file | head to verify local context
  • Use head, tail, and sed for fine-grained snippet inspection

These operations can be composed into pipelines, iteratively refined, and precisely targeted—what the paper calls "interface resolution."

On the left is traditional retrieval: a black box takes a query and returns a document list.
On the right is DCI: a toolbox lets you browse, search, locate, and extract information, interacting with the corpus like a person.

How Good Are the Results?

The paper tests three categories of tasks:

1. Deep Research Tasks (BrowseComp-Plus)

This is a complex question-answering benchmark requiring multistep reasoning.

Results:

  • Using the same Claude Sonnet 4.6 model
  • Replacing the Qwen3-Embedding-8B retriever with DCI
  • Accuracy rises from 69.0% to 80.0% (+11 percentage points)
  • Cost falls from 1,016 (−29.4%)

The lighter DCI-Agent-Lite, using GPT-5.4 nano, costs only 740), while achieving comparable performance.

2. Multi-hop Question Answering

Across six datasets, including NQ, TriviaQA, HotpotQA, and MuSiQue:

  • DCI-Agent-CC (Claude Sonnet 4.6) achieves 83.0% average accuracy
  • The strongest retrieval-agent baseline, ASearcher-Local-14B, achieves only 52.3%
  • An improvement of 30.7 percentage points

Gains are particularly pronounced on multi-hop tasks:

  • HotpotQA: +30 points
  • 2WikiMultiHopQA: +26 points
  • MuSiQue: +50 points


    The upper half is Table 2 (multi-hop QA); the lower half is Table 3 (IR ranking).
    DCI-Agent ranks first on almost every dataset.

3. Information Retrieval Ranking

On BRIGHT and BEIR:

  • DCI-Agent-CC reaches an average NDCG@10 of 68.5
  • The strongest retrieval baseline, ReasonRank-32B, reaches only 47.0
  • An improvement of 21.5 points

Why DCI Works

A series of controlled experiments leads the paper to this conclusion:

DCI's advantage is not that it finds more relevant documents, but that it makes finer-grained use of the documents it has already found.

Key Numbers

On BrowseComp-Plus, using the same Sonnet 4.6 model:

  • DCI-Agent-CC correctly answers 176 questions that the retrieval agent gets wrong
  • The retrieval agent correctly answers only 76 questions that DCI gets wrong

But here is the key point:Of those 176 questions, only 34 involve the retrieval agent failing to find any relevant documents.

For the other 142, the retrieval agent actually finds at least one relevant document but still answers incorrectly. These failures fall into two categories:

  1. 1. Partial-chain failures (83 questions): Some evidence is found, but it is incomplete and cannot support the next reasoning step
  2. 2. Post-retrieval failures (59 questions): All relevant documents are found, but are not used effectively

Tool-use Analysis

DCI-Agent-CC's tool-call distribution:

  • Bash commands: 62.4%
    • Chained search: 22.3%
    • Local context peeking: 18.0%
    • Regex matching: 17.0%
    • File localization: 14.0%
    • Full-document reads: only 9.1%
  • Grep searches: 33.0%

What does this tell us?DCI's advantage comes from composing Bash commands to manipulate documents precisely: combining lexical constraints, verifying exact snippets, and selectively expanding promising passages.

This figure reveals why DCI succeeds.The left panel shows that its advantage extends beyond finding documents: fine-grained operations extract evidence that traditional interfaces obscure, even from documents already discovered by the retriever.The right panel shows what this "high resolution" looks like in practice: instead of reading blindly, agents frequently use precise tools such as chained search (22.3%) and snippet peeking (18.0%) to pinpoint answers.

Coverage vs. Localization

The paper defines two metrics:

  • Coverage: How many relevant documents are found
  • Localization: How precisely useful snippets can be located within those documents

The results are interesting:

DCI's mean coverage (28.0) is far below the retrieval baseline (56.7), but its coverage of "at least one" relevant document (70.0) is close to the baseline's 74.0, while its localization score (48.4) is more than twice the retrieval baseline's 21.7.

In other words:DCI wins through precise use, rather than exhaustive discovery.

Although L3 has the lowest coverage (27.0), it has the strongest localization and ultimately the highest accuracy (77).

Once DCI finds a useful document, it can switch from broad retrieval to detailed inspection and verification, extracting more value from what it already has.

DCI's Limitations

The paper also candidly identifies DCI's boundaries:

1. Sensitivity to Corpus Size

DCI performs well on search depth, but its cost rises quickly with search breadth.

Expanding the BrowseComp-Plus corpus from 100,000 to 200,000 documents:

  • Tool calls rise from 38.5 to 86.9
  • Latency doubles
  • Cost doubles
  • Accuracy drops by 13.6 points

At 400,000 documents:

  • Accuracy falls to 37.5%
  • Average tool calls reach 122.4
  • Twenty samples terminate after exceeding the tool budget

Conclusion: DCI suits small-to-medium corpora around 100,000 documents, rather than large corpora numbering in the millions.

2. Context Management Is Critical

The paper tests five context-management strategies, L0 through L4, and finds:

  • The most aggressive compression (L2) has the lowest cost but the worst accuracy (69%)
  • The most conservative strategy (L1) retains the most evidence but does not achieve the highest accuracy (75%)
  • The best strategy (L3) achieves the highest accuracy (77%) and also the highest cost

Conclusion: Context management is not about keeping more of everything; it requires selective forgetting—retaining intermediate structures useful to later searches while discarding redundant verbatim evidence.

3. Tool Expressiveness Matters

The paper compares two tool configurations:

  • read + grep (restricted toolset): 61% accuracy, $0.0355 cost
  • Open bash (full toolset): 73% accuracy, $0.1021 cost

Conclusion: Composable tools—Bash pipes, regex, and conditionals—are critical to DCI's effectiveness.

Why This Paper Matters

1. Redefining the Retrieval Bottleneck

Traditional view: the bottleneck is failing to find relevant documents.

This paper: the bottleneck is low interface resolution—even found documents cannot be manipulated precisely.

2. Introducing "Interface Resolution"

Interface Resolution: How fine-grained is the smallest unit the agent can manipulate?

  • Traditional retrieval: documents or paragraphs (coarse-grained)
  • DCI: lines, snippets, or regex matches (fine-grained)

Higher resolution allows finer operations: verifying hypotheses, combining clues, and iteratively refining searches.

3. Challenging the Assumption That an Index Is Necessary

Traditional RAG systems require an index—embeddings plus a vector database—before retrieval.

DCI needs no index and operates on raw files through terminal tools.

This is particularly useful for local, dynamic, and heterogeneous corpora: no offline indexing is required, and changes to files are handled naturally.

4. Pointing the Way for Agent Design

When a model is strong enough to search like a human researcher—forming hypotheses, testing patterns, reading context, and refining queries—a compressed similarity index becomes a bottleneck. At that point, a high-resolution interface matters more than a high-quality retriever.

In other words:Retrieval is not just a retriever-design problem; it is an interface-design problem.

Use Cases

Based on the paper's experimental results, DCI is suitable for:

✅ Suitable Scenarios

  1. 1. Small-to-medium corpora (up to 100,000 documents)
  2. 2. Complex tasks requiring multistep reasoning (multi-hop QA and deep research)
  3. 3. Tasks requiring precise lexical constraints ("must contain both A and B")
  4. 4. Local or dynamic corpora (files change frequently and you do not want to maintain an index)
  5. 5. Tasks requiring precise evidence localization (finding specific snippets as well as documents)

❌ Unsuitable Scenarios

  1. 1. Large corpora (millions of documents or more)
  2. 2. Simple single-hop QA (traditional retrieval is already sufficient)
  3. 3. Tasks requiring semantic generalization (such as finding similar concepts)
  4. 4. Latency-sensitive tasks (DCI requires multiple tool calls)

Technical Details

Two Implementations

The paper implements two versions:

  1. 1. DCI-Agent-Lite
    • Built on Pi, a minimal terminal harness
    • Exposes only bash and read as its two tools
    • Uses GPT-5.4 nano, a lightweight model
    • Low cost ($93 for 830 questions)
    • 62.9% accuracy on BrowseComp-Plus
  2. 2. DCI-Agent-ClaudeCode (CC)
    • Built on Claude Code
    • Uses Claude Sonnet 4.6, a high-performance model
    • High cost ($1,016 for 830 questions)
    • 80.0% accuracy on BrowseComp-Plus

Evaluation Metrics

The paper introduces a new metric:Localization Score

  • Measures how precisely an agent locates useful snippets
  • Measures finding specific evidence within a document, rather than merely finding the document
  • Calculation: find the best snippet-level match score for each relevant document, then average

This metric matters because it distinguishes finding documents from using them well.

Future Directions

The paper also identifies several directions worth exploring:

1. Hybrid Interfaces

Instead of choosing exclusively between retrievers and DCI:

  • Use a retriever for coarse filtering to narrow the search quickly
  • Use DCI for detailed inspection of candidate documents

This can combine scale with precision.

2. Better Context Management

The paper finds that context-management strategies strongly affect DCI, but has not yet found the optimal strategy.

Future possibilities include:

  • Learning context-management policies through reinforcement learning
  • Adjusting compression strength dynamically by task type
  • Retaining useful intermediate structures instead of verbatim evidence

3. Tool Learning

Teach agents:

  • When to use grep versus find
  • How to combine tools through Bash pipelines
  • How to adjust search strategies based on intermediate results

4. Scaling

How can DCI handle larger corpora?

Possible directions:

  • Hierarchical indexing: coarse-grained indexes plus fine-grained DCI
  • Incremental indexing: index only metadata and use DCI for content
  • Distributed DCI: search multiple subcorpora in parallel

Summary

Retrieval's bottleneck lies in using evidence poorly, rather than failing to find it.

Traditional retrieval gives agents a low-resolution interface—top-k documents—that limits their action space.

DCI provides a high-resolution interface—raw files plus terminal tools—so agents can work precisely like human researchers: combining clues, testing hypotheses, and refining their approach.

The experiments demonstrate:When the model is strong enough, interface resolution matters more than retriever quality.

This does not mean retrievers are useless. It means:We need to rethink how agents interact with corpora.

Retrieval is not just a retriever-design problem; it is an interface-design problem.
