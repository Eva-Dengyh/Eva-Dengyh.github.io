1. Where the tool system fits in the architecture

Recall the previous chapter's overall architecture. The tool system is at the bottom:

┌─────────────────────────────────────────────────┐
│              Hermes Gateway                      │
│              (消息进 / 消息出)                    │
└─────────────────────┬───────────────────────────┘
                      │
┌─────────────────────┴───────────────────────────┐
│              run_agent.py                        │
│         AI 循环：问模型 → 执行工具 → 问模型       │
└─────────────────────┬───────────────────────────┘
                      │ 工具调用
┌─────────────────────┴───────────────────────────┐
│           tools/registry.py                     │
│         （工具注册中心）                          │
│         tools/file_tools.py                     │
│         tools/terminal_tool.py                  │
│         tools/web_tools.py                      │
│         tools/delegate_tool.py                  │
│         ...（60+ 工具）                          │
└─────────────────────────────────────────────────┘

In one sentence: the tool system is Hermes' hands—all interactions with the outside world, including reading files, searching the web, and executing commands, happen through tools.

2. The registry pattern in detail

2.1 What is the registry pattern?

An everyday analogy: It resembles a company's front-desk register. Each new employee fills in their own entry: “My name is XX, my desk is YY, and I can do ZZ.” Visitors consult the register to find someone without knowing where they live or what they like.

The code analogy:

# 传统方式（耦合）：
class FileTools:
    def read_file(self, path): ...
    def write_file(self, path, content): ...

class TerminalTools:
    def run_command(self, cmd): ...

# 每加一个工具 → 改一次类的定义 → 核心代码越来越臃肿

# 注册表方式（解耦）：
registry = ToolRegistry()

def read_file_handler(args): 
    return read_file(args["path"])

registry.register(
    name="read_file",
    schema={...},      # 给 AI 看的说明
    handler=read_file_handler  # 真正做事的函数
)

# 新增工具？完全不需要动 registry.py
# 只需要在工具文件里加一行 registry.register(...)

2.2 ToolRegistry's data structure

class ToolRegistry:
    def __init__(self):
        self._tools: Dict[str, ToolEntry] = {}
        # 注册表本体：名字 → 工具条目

    def register(self, name, schema, handler, ...):
        entry = ToolEntry(name, schema, handler, ...)
        self._tools[name] = entry  # 注册动作

    def get(self, name) -> ToolEntry:
        return self._tools.get(name)  # 查询动作

    def dispatch(self, name, args) -> str:
        entry = self.get(name)
        return entry.handler(args)  # 执行动作

2.3 Why not class inheritance?

With traditional object-oriented design, tools would form an inheritance tree like this:

Tool
├── FileTool
│   ├── ReadFileTool
│   ├── WriteFileTool
│   └── SearchFilesTool
├── TerminalTool
│   ├── RunCommandTool
│   └── BackgroundProcessTool
└── WebTool
    ├── SearchTool
    └── BrowserTool

Problems:

  • Python does not support multiple inheritance, but tools often need several capabilities simultaneously, such as both reading/writing files and executing commands
  • Adding a tool requires changing the class hierarchy
  • Testing is complex because every subclass must be instantiated

Advantages of the registry pattern:

  • Tools are independent, without a hierarchy
  • A new tool requires only a new file and one registration line
  • Tests can target individual tools without constructing an inheritance tree

3. Schema: An instruction manual for the AI model

3.1 What is a schema?

A schema is a JSON object describing:

工具叫什么名字
接受哪些参数（名字、类型、含义）
工具是做什么的
返回什么格式

It is a tool manual for the AI model, rather than for humans.

3.2 Schema structure

Take the read_file tool as an example:

{
  "name": "read_file",
  "description": "Read a text file with pagination and line numbers.\n\n"
                "Use this instead of cat/head/tail in terminal.\n\n"
                "Output format: 'LINE_NUM|CONTENT'.\n\n"
                "Args:\n"
                "  path (str): Path to the file (absolute, relative, or ~/path)\n"
                "  offset (int): Line number to start reading from (1-indexed)\n"
                "  limit (int): Maximum lines to read (default 500, max 2000)\n\n"
                "Returns:\n"
                "  dict with 'content', 'total_lines', 'is_binary', 'is_image'",
  "parameters": {
    "type": "object",
    "properties": {
      "path": {
        "type": "string",
        "description": "Path to the file to read (absolute, relative, or ~/path)"
      },
      "offset": {
        "type": "integer",
        "description": "Line number to start reading from (1-indexed, default: 1)",
        "default": 1
      },
      "limit": {
        "type": "integer", 
        "description": "Maximum number of lines to read (default: 500, max: 2000)",
        "default": 500
      }
    },
    "required": ["path"]
  }
}

3.3 How does the AI model use a schema?

AI 模型看到 Schema 后：

"好的，我有一个叫 read_file 的工具。
 它接受一个叫 path 的字符串参数（必填），
 还有 offset 和 limit 两个可选整数参数。
 当用户让我'看看某个文件内容'时，我就知道要调用它。"

这是 LLM 的 function calling 能力——模型根据对话上下文，
自动决定调用哪个工具、传什么参数。

3.4 Best practices for writing schemas

A good schema:

  • Describes parameters clearly, including when each should be used
  • States default values when present
  • Uses descriptions to explain usage scenarios, beyond parameter meanings

A poor schema:

{
  "name": "weather",
  "description": "Get weather",
  "parameters": {
    "properties": {"city": {"type": "string"}}
  }
}

A good schema:

{
  "name": "weather",
  "description": "Get current weather and forecast for a city.\n\n"
                "Use when: user asks about weather, temperature, rain, etc.\n\n"
                "Returns: temperature, conditions, humidity, forecast.",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "City name (e.g. 'Beijing', 'Tokyo')"
      },
      "forecast_days": {
        "type": "integer", 
        "description": "Number of days to forecast (1-7, default: 3)",
        "default": 3
      }
    },
    "required": ["city"]
  }
}

4. Handler: The Python function that does the work

4.1 A handler's responsibilities

A handler is a plain Python function responsible for:

  1. 1. Receiving arguments as a dictionary
  2. 2. Performing the actual operation
  3. 3. Returning a JSON string (all tools must return JSON strings)

4.2 Standard handler signature

def my_handler(args: dict, **kwargs) -> str:
    """
    Args:
        args: 工具调用时传递的参数（字典）
        **kwargs: 额外上下文
            task_id: str      # 终端/浏览器会话隔离 ID
            session_id: str   # 会话 ID
            tool_call_id: str # 工具调用 ID（用于 trace）
    
    Returns:
        str: JSON 字符串（必须能 json.loads）
    """
    # 解析参数
    param1 = args.get("param1", "default")
    param2 = args.get("param2", 0)
    
    try:
        # 做实际的事
        result = do_something(param1, param2)
        
        # 返回 JSON 字符串
        return json.dumps({"success": True, "result": result})
    
    except Exception as e:
        # 错误也要返回 JSON 字符串
        return json.dumps({"error": f"Failed: {str(e)}"})

4.3 Why return a JSON string?

Because this return value is eventually inserted into the AI model's conversation history:

# AI 模型看到工具执行结果后，继续思考下一步

messages = [
    {"role": "user", "content": "帮我读 test.py"},
    {"role": "assistant", "tool_calls": [{"name": "read_file", "args": {"path": "test.py"}}]},
    {"role": "tool", "content": '{"content": "...file contents...", "total_lines": 50}'},
    #                                                      ↑
    #                                           必须是字符串，因为 role: tool 的
    #                                           content 字段在 API 规范里是字符串
]

4.4 A real handler example

Here is the implementation of todo_tool (tools/todo_tool.py):

class TodoStore:
    """内存中的任务清单，一个 AIAgent 实例对应一个。"""
    def __init__(self):
        self._items: List[Dict[str, str]] = []

    def write(self, todos: List[Dict], merge: bool = False) -> List[Dict]:
        if not merge:
            # 全量替换模式
            self._items = [self._validate(t) for t in self._dedupe(todos)]
        else:
            # 合并模式：按 id 更新已有项，追加新项
            existing = {item["id"]: item for item in self._items}
            for t in todos:
                item_id = t.get("id", "").strip()
                if item_id in existing:
                    # 更新字段
                    if "content" in t: existing[item_id]["content"] = t["content"]
                    if "status" in t: existing[item_id]["status"] = t["status"]
                else:
                    # 追加新项
                    self._items.append(self._validate(t))
        return self.read()  # 总是返回完整列表


def todo_tool(todos=None, merge=False, store=None) -> str:
    """
    Args:
        todos: 任务列表 [{id, content, status}]
        merge: 是否合并（True=更新已有，False=全量替换）
        store: TodoStore 实例（从 AIAgent 注入）
    """
    if todos is None:
        # 读模式：没有 todos 参数
        return json.dumps({"todos": store.read()})
    
    # 写模式
    result = store.write(todos, merge=merge)
    return json.dumps({"todos": result})

5. Discovery: How tools are found

5.1 Introducing the problem

With over 60 tools, manually importing every file at startup would be verbose:

# ❌ 错误方式：维护一个巨大的 import 列表
import tools.todo_tool
import tools.file_tools
import tools.terminal_tool
import tools.web_tools
# ... 60 行...

# 如果要加一个新工具，要改这个列表

5.2 Hermes' solution: Automatic discovery

model_tools.py dynamically imports every tool during module loading through importlib:

def _discover_tools():
    """
    导入所有工具模块。
    每个模块在 import 时，末尾的 registry.register() 自动执行。
    这样新增工具只需要新增文件，不需要改这个列表。
    """
    _modules = [
        "tools.ansi_strip",

        "tools.browser_tool",
        "tools.budget_config",
        "tools.checkpoint_manager",

        "tools.cronjob_tools",
        "tools.debug_helpers",
        "tools.delegate_tool",
        "tools.env_passthrough",
        "tools.file_operations",
        "tools.file_tools",
        "tools.fuzzy_match",
        "tools.homeassistant_tool",
        "tools.image_generation_tool",
        "tools.interrupt",
        "tools.managed_tool_gateway",

5.3 Automatic registration during module loading

Take file_tools.py as an example. At the end of the file:

registry.register(

registry.register(

registry.register(name="patch", ...)
registry.register(name="search_files", ...)

When importlib.import_module("tools.file_tools") executes, Python runs the file from beginning to end. The final registry.register() registers the tool.

Adding a tool requires just two things:

6. Tracing the complete invocation path

6.1 The full path from user input to tool execution

用户："帮我读取 test.py"

        │
        ▼ ① Gateway 适配器解析用户消息
           unified_message = {user_id, text: "帮我读取 test.py", ...}
        │
        ▼ ② run_agent.run_conversation()
           把消息加入 messages[]
        │
        ▼ ③ 组装系统提示词（prompt_builder）
        │
        ▼ ④ 发 API 给 AI 模型
           client.chat.completions.create(
               messages=[系统提示词, 用户消息],
               tools=[read_file schema, write_file schema, ...]
           )
        │
        ▼ ⑤ AI 模型思考，决定调用 read_file
           response.tool_calls = [
               {"name": "read_file", "args": {"path": "test.py", "offset": 1, "limit": 500}}
           ]
        │
        ▼ ⑥ 主循环发现 tool_calls，执行工具
           from model_tools import handle_function_call
           │
           ▼ ⑦ handle_function_call 路由
              │
              ▼ ⑧ registry.dispatch("read_file", args)
                 │
                 ▼ ⑨ 找到 read_file 的 ToolEntry
                    entry = registry._tools["read_file"]
                    │
                    ▼ ⑩ 调用 handler
                       result = entry.handler(args)
                       # 内部执行 open("test.py").read()
                       # 返回 json.dumps({"content": "...", "total_lines": 50})
                    │
                    ▼ ⑪ 把结果加回 messages[]
                    messages.append({
                        "role": "tool",
                        "tool_call_id": "xxx",
                        "content": '{"content": "...", "total_lines": 50}'
                    })
                 │
                 ▼ ⑫ 回到循环开头，再次发 API 给模型
                    "用户要我读文件，我已经读完了，这是内容：..."
        │
        ▼ ⑬ AI 模型看到文件内容，组织语言回复用户
           最终回复（无 tool_calls）→ break 循环
        │
        ▼ ⑭ Gateway 把回复发回给用户

6.2 What does handle_function_call do?

# model_tools.py

def handle_function_call(
    function_name: str,
    function_args: Dict[str, Any],
    task_id: Optional[str] = None,
    tool_call_id: Optional[str] = None,
    session_id: Optional[str] = None,
    user_task: Optional[str] = None,
    enabled_tools: Optional[List[str]] = None,
    skip_pre_tool_call_hook: bool = False,
) -> str:
    """
    工具调用的分发入口。
    所有工具调用都经过这里。
    """
    # 第1步：类型强制转换（"42" → 42, "true" → True）
    function_args = coerce_tool_args(function_name, function_args)
    
    # 第2步：插件钩子（pre_tool_call）
    # 允许插件在工具执行前拦截或阻止
    if not skip_pre_tool_call_hook:
        block_message = get_pre_tool_call_block_message(...)
        if block_message is not None:
            return json.dumps({"error": block_message})
    
    # 第3步：执行工具
    if function_name == "execute_code":
        # execute_code 比较特殊，需要传入 enabled_tools
        result = registry.dispatch(
            "execute_code", function_args,
            task_id=task_id,
            enabled_tools=enabled_tools
        )
    else:
        result = registry.dispatch(
            function_name, function_args,
            task_id=task_id,
            user_task=user_task
        )
    
    # 第4步：插件钩子（post_tool_call）
    invoke_hook("post_tool_call", tool_name=function_name, ...)
    
    return result

6.3 What does registry.dispatch do?

# tools/registry.py

class ToolRegistry:
    def dispatch(self, name: str, args: dict, **kwargs) -> str:
        """根据名字找到工具，执行它，返回 JSON 字符串。"""
        
        # 第1步：找到工具条目
        entry = self.get_entry(name)
        if not entry:
            return json.dumps({"error": f"Unknown tool: {name}"})
        
        # 第2步：调用 handler
        try:
            if entry.is_async:
                # 异步工具（使用了 async def 的工具）
                from model_tools import _run_async
                return _run_async(entry.handler(args, **kwargs))
            return entry.handler(args, **kwargs)
        
        # 第3步：异常处理
        except Exception as e:
            logger.exception("Tool %s dispatch error: %s", name, e)
            return json.dumps({
                "error": f"Tool execution failed: {type(e).__name__}: {e}"
            })

7. Toolsets: Managing tools in groups

7.1 Why are toolsets needed?

With over 60 tools, disabling all file-operation tools would otherwise require configuring each individually:

# ❌ 没有工具集时：
disabled_tools = ["read_file", "write_file", "patch", "search_files", ...]

With a toolset, one configuration line is enough:

# ✅ 有工具集时：
disabled_toolsets = ["file"]  # 关闭整个 file 工具组

7.3 Toolset availability checks

Each tool can declare a check_fn (availability-check function):

def _check_file_reqs() -> bool:
    """文件工具：始终可用（纯本地操作）"""
    return True

def _check_browser_reqs() -> bool:
    """浏览器工具：需要 BROWSERBASE_API_KEY"""
    import os
    return bool(os.getenv("BROWSERBASE_API_KEY"))

registry.register(
    name="browser_navigate",
    toolset="browser",
    schema=BROWSER_NAVIGATE_SCHEMA,
    handler=browser_navigate,
    check_fn=_check_browser_reqs,  # 没有 API Key 时自动不可用
    requires_env=["BROWSERBASE_API_KEY"],
)

8. Hands-on: Adding a weather-query tool to Hermes

8.1 Goal

Create a weather tool:

  • Input: City name as a string
  • Output: Weather information—temperature, humidity, and conditions
  • Calls an external weather API

8.2 Step 1: Create the tool file

# tools/weather_tool.py

import json
import os
import urllib.request
from typing import Dict, Any

# ============================================================
# Schema：给 AI 模型看的说明书
# ============================================================

WEATHER_SCHEMA = {
    "name": "weather",
    "description": (
        "Get current weather and forecast for a city.\n\n"
        "Use when: user asks about weather, temperature, rain, whether to bring an umbrella, etc.\n\n"
        "Returns: temperature (°C), conditions, humidity (%), wind speed, and forecast for 3 days.\n\n"
        "Note: Weather data from wttr.in (no API key required)."
    ),
    "parameters": {
        "type": "object",
        "properties": {
            "city": {
                "type": "string",
                "description": (
                    "City name or location. "
                    "Examples: 'Beijing', 'Tokyo', 'New York', 'London UK', 'Tokyo JP'"
                )
            }
        },
        "required": ["city"]
    }
}

# ============================================================
# Handler：真正做事的函数
# ============================================================

def check_weather_requirements() -> bool:
    """weather 工具不需要 API key，wttr.in 是免费服务"""
    return True

def weather_tool(city: str, task_id: str = "default") -> str:
    """
    获取城市天气信息。
    
    Args:
        city: 城市名
        task_id: 任务 ID（用于缓存等）
    
    Returns:
        JSON 字符串，包含天气信息
    """
    if not city or not city.strip():
        return json.dumps({"error": "City name is required"})
    
    city = city.strip()
    
    try:
        # wttr.in 是一个免费的天气预报服务，不需要 API key
        # 格式：JSON
        url = f"https://wttr.in/{city}?format=j1"
        
        req = urllib.request.Request(
            url,
            headers={"User-Agent": "Mozilla/5.0 Hermes-Agent"}
        )
        
        with urllib.request.urlopen(req, timeout=10) as response:
            data = json.loads(response.read().decode("utf-8"))
        
        # 解析 wttr.in 的返回格式
        current = data["current_condition"][0]
        nearest_area = data["nearest_area"][0]
        
        result = {
            "city": nearest_area.get("areaName", [{}])[0].get("value", city),
            "country": nearest_area.get("country", [{}])[0].get("value", ""),
            "temperature_c": current["temp_C"],
            "feels_like_c": current["FeelsLikeC"],
            "humidity": current["humidity"],
            "weather": current["weatherDesc", [{}])[0].get("value", ""),
            "wind_speed_kmh": current["windspeedKmph"],
            "wind_dir": current["winddir16Point"],
            "uv_index": current["uvIndex"],
            "forecast": []
        }
        
        # 解析 3 天预报
        for day in data["weather"]:
            result["forecast"].append({
                "date": day["date"],
                "max_temp_c": day["maxtempC"],
                "min_temp_c": day["mintempC"],
                "avg_temp_c": day["avgtempC"],
                "condition": day["hourly"][4]["weatherDesc"][0]["value"],
            })
        
        return json.dumps({
            "success": True,
            "data": result
        })
    
    except urllib.error.URLError as e:
        return json.dumps({
            "error": f"Failed to fetch weather for '{city}': network error. "
                     f"Please check the city name and try again."
        })
    except Exception as e:
        return json.dumps({
            "error": f"Failed to fetch weather: {str(e)}"
        })

# ============================================================
# 注册到全局注册表
# ============================================================

from tools.registry import registry

registry.register(
    name="weather",
    toolset="web",          # 天气属于 web 工具集（依赖网络）
    schema=WEATHER_SCHEMA,
    handler=lambda args, **kw: weather_tool(
        city=args.get("city", ""),
        task_id=kw.get("task_id", "default")
    ),
    check_fn=check_weather_requirements,
    emoji="🌤️",
)

8.5 Reviewing the complete invocation path

用户问天气
    │
    ▼ AI 模型决定调用 weather(city="北京")
    │
    ▼ model_tools.handle_function_call("weather", {"city": "北京"})
    │
    ▼ registry.dispatch("weather", args)
    │
    ▼ weather_tool(city="北京")
         │
         ▼ urllib.request.urlopen("https://wttr.in/北京?format=j1")
         │
         ▼ 解析 JSON 返回
         │
         ▼ json.dumps({"success": true, "data": {...}})
    │
    ▼ 结果回到 AI 模型
    │
    ▼ AI 组织自然语言回复用户
