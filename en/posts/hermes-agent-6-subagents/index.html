1. What problems do subagents solve?

1.1 The single-agent bottleneck

A standard AIAgent works on one thread:

用户：帮我研究 AI Agent 的最新发展

    AI 思考：需要搜索很多资料...
        │
        ▼
    搜索 ①：LangChain 最新动态
        │
        ▼ 等待结果
    分析 ①
    
    搜索 ②：AutoGen 最新动态
        │
        ▼ 等待结果
    分析 ②
    
    搜索 ③：CrewAI 最新动态
        │
        ▼ 等待结果
    分析 ③
    
    综合报告 → 返回用户

The problem: Search and analysis are sequential, so three topics take three times as long.

1.2 The subagent solution

Introduce multiple subagents working simultaneously:

用户：帮我研究 AI Agent 的最新发展

    主 Agent（你）
        │
        ├──▶ 子 Agent A：研究 LangChain
        │       搜索 ① → 分析 ①
        │
        ├──▶ 子 Agent B：研究 AutoGen
        │       搜索 ② → 分析 ②
        │
        └──▶ 子 Agent C：研究 CrewAI
                搜索 ③ → 分析 ③

    三个子 Agent 同时工作（并行）
        │
        ▼
    主 Agent 收集所有结果 → 综合报告 → 返回用户

Result: Researching three topics takes 1x rather than 3x the time.

2. What is a subagent?

2.1 Definition

A subagent is a complete AIAgent instance running in an independent context.

主 Agent（父）
    │
    ├── 共享：主 Agent 的 session_id（用于共享历史）
    ├── 独立：自己的 AIAgent 实例
    ├── 独立：自己的 messages[] 历史
    ├── 独立：自己的 task_id（用于隔离工具状态）
    └── 独立：自己的 toolsets 配置

2.2 Subagents versus threads

People often confuse subagents with multithreading:

多线程：
  - 同一个进程里，多个执行流同时跑
  - 共享内存，有竞态条件风险
  - 一个崩溃可能影响其他

子 Agent：
  - 独立的 AIAgent 实例（进程级别隔离）
  - 完全独立的上下文
  - 一个崩溃不影响其他
  - 通信通过消息（JSON 字符串）

2.3 When to use subagents

ScenarioWhy use a subagent?
Research multiple topics at onceSpeed through parallelism
Handle subtasks in complex workTask decomposition and focus
Run risky operations that might failProtection through isolation
Tasks requiring different toolsetsIndependent configuration

3. The design of delegate_tool

3.1 Tool signature

# tools/delegate_tool.py

DELEGATE_SCHEMA = {

    "description": (

                "items": {

3.2 Core logic of delegate_tool

# tools/delegate_tool.py（简化版）

def delegate_task(
    goal: str = None,
    context: str = None,
    toolsets: List[str] = None,
    tasks: List[dict] = None,
    # 以下参数由框架注入
    task_id: str = None,
    session_id: str = None,
) -> str:
    """
    创建子 Agent 并执行任务。
    """
    
    # ========== 单任务模式 ==========
    if goal and not tasks:
        subagent = AIAgent(
            session_id=f"{session_id}:subagent:{task_id}",
            enabled_toolsets=toolsets or ["terminal", "file", "web"],
        )
        
        result = subagent.run_conversation(
            user_message=goal,
            system_message=f"Context: {context}" if context else None,
        )
        
        return json.dumps({
            "success": True,
            "result": result["final_response"],
        })
    
    # ========== 批量并行模式 ==========
    if tasks:
        # 并行执行多个子任务
        with concurrent.futures.ThreadPoolExecutor(max_workers=3) as executor:
            futures = []
            for i, task in enumerate(tasks):
                future = executor.submit(
                    run_subagent, task, i, session_id
                )
                futures.append(future)
            
            # 等待所有完成
            results = [f.result() for f in futures]
        
        return json.dumps({
            "success": True,
            "results": results,
        })

3.3 Batch mode: Parallel tasks

# 批量模式的实现

async def run_subagent_batch(tasks: List[dict]) -> List[str]:
    """
    同时启动多个子 Agent，结果一起返回。
    这是 Hermes 实现"同时研究 3 个主题"的核心。
    """
    
    async def run_one(task: dict, index: int):
        subagent = AIAgent(
            session_id=f"batch:{session_id}:{index}",
            enabled_toolsets=task.get("toolsets", ["terminal", "file", "web"]),
        )
        
        return await subagent.run_conversation_async(
            user_message=task["goal"],
            system_message=f"Background: {task.get('context', '')}",
        )
    
    # asyncio.gather 同时运行所有任务
    results = await asyncio.gather(
        *[run_one(t, i) for i, t in enumerate(tasks)]
    )
    
    return results

4. A subagent's lifecycle

4.1 Complete lifecycle diagram

主 Agent
    │
    │ ① delegate_task("帮我研究 X", tasks=[A, B, C])
    ▼
子 Agent A  子 Agent B  子 Agent C
    │          │          │
    │ ② 创建   │  ③ 创建   │  ④ 创建
    │ AIAgent │  AIAgent │  AIAgent
    │ 实例     │  实例     │  实例
    │          │          │
    │ ⑤ 运行   │  ⑤ 运行   │  ⑤ 运行
    │ run_conv │  run_conv │  run_conv
    │          │          │
    │ ⑥ 返回   │  ⑥ 返回   │  ⑥ 返回
    │ 结果     │  结果     │  结果
    │          │          │
    └──────────┼──────────┘
               │
               ▼
         ⑦ 主 Agent 收集所有结果
               │
               ▼
         ⑧ 综合成最终回复
               │
               ▼
         ⑨ 返回给用户

4.2 Lifecycle in detail

① 创建子 Agent
   - 主 Agent 调用 delegate_task
   - 框架创建一个全新的 AIAgent 实例
   - 每个子 Agent 有自己的 task_id

② 初始化上下文
   - 子 Agent 加载自己的 system prompt
   - 如果传入了 context，作为 system message 注入
   - 子 Agent 不知道主 Agent 聊过什么

③ 运行 run_conversation
   - 子 Agent 独立执行 AI 循环
   - 可以调用工具，可以多轮交互
   - 有自己的 iteration_budget

④ 返回结果
   - 子 Agent 返回 final_response
   - 结果以 JSON 字符串形式返回给主 Agent
   - 主 Agent 把结果注入自己的 messages

⑤ 主 Agent 继续工作
   - 主 Agent 看到子 Agent 的结果
   - 综合所有子 Agent 的研究，生成最终报告

4.3 State isolation

The subagent and main agent are fully isolated:

# 隔离维度：

# 消息历史（messages[]）
主 Agent messages ≠ 子 Agent messages
  → 子 Agent 不会看到主 Agent 的完整对话历史

# 工具状态
子 Agent 有独立的 task_id
  → 子 Agent 的文件操作不会污染主 Agent 的工作目录

# 工具集（toolsets）
子 Agent 可以有不同的工具集
  → 可以限制子 Agent 只能搜索，不能写文件

# Token 预算
每个子 Agent 有自己的 iteration_budget
  → 一个子 Agent 失控不会耗尽主 Agent 的预算

5. Parallel execution: Multiple subagents working together

5.1 Why parallelize?

Running three subagents sequentially:

任务 A：10 分钟
任务 B：10 分钟
任务 C：10 分钟
─────────────────
总耗时：30 分钟

Running three subagents in parallel:

子A：10分钟 ──────────────────▶
子B：10分钟 ──────────────────▶
子C：10分钟 ──────────────────▶
─────────────────
总耗时：10 分钟

5.2 Conditions for parallel execution

Parallelism is not universal. It suits the following situations:

适合并行：
  ✅ 三个任务相互独立（研究 A、研究 B、研究 C）
  ✅ 三个任务不需要互相通信
  ✅ 三个任务使用不同的工具

不适合并行：
  ❌ 任务 B 需要等任务 A 的结果
  ❌ 三个任务要访问同一个文件
  ❌ 三个任务有执行顺序依赖

5.3 Using batch mode

# 批量并行模式的调用方式

delegate_task(
    tasks=[
        {
            "goal": "深入研究 LangChain 的最新发展",
            "context": "重点关注：1) 新特性 2) 性能改进 3) 已知问题",
            "toolsets": ["web", "terminal"],
        },
        {
            "goal": "深入研究 AutoGen 的最新发展",
            "context": "重点关注：1) 多 Agent 协作 2) 代码生成能力",
            "toolsets": ["web", "terminal"],
        },
        {
            "goal": "深入研究 CrewAI 的最新发展",
            "context": "重点关注：1) Agent 角色定义 2) 任务分解能力",
            "toolsets": ["web", "terminal"],
        },
    ]
)
# → 三个子 Agent 同时启动
# → 10 分钟后，三个结果一起返回
# → 主 Agent 综合成报告

5.4 Technical implementation of parallel execution

# ThreadPoolExecutor 实现真正的并行

with concurrent.futures.ThreadPoolExecutor(max_workers=3) as executor:
    
    def run_subagent_in_thread(task: dict, index: int):
        """在新线程里运行子 Agent"""
        subagent = AIAgent(
            session_id=f"{session_id}:child:{index}",
            enabled_toolsets=task.get("toolsets", ["terminal", "file", "web"]),
        )
        
        return subagent.run_conversation(
            user_message=task["goal"],
            system_message=task.get("context"),
        )
    
    futures = [
        executor.submit(run_subagent_in_thread, task, i)
        for i, task in enumerate(tasks)
    ]
    
    # gather 等待所有线程完成
    results = [f.result() for f in concurrent.futures.as_completed(futures)]

6. Tool-call flow: Main agent ↔ Subagent

6.1 Can subagents call tools?

Yes. A subagent is a full AIAgent with its own toolset.

子 Agent A
    │
    │ user_message: "搜索 LangChain 最新动态"
    ▼
AI 思考："需要调用 web_search 工具"
    │
    ▼
web_search(query="LangChain latest news 2025")
    │
    ▼
返回搜索结果

6.2 Subagent tool restrictions

The main agent can restrict which tools a subagent may use:

delegate_task(
    goal="帮我分析这个代码库",
    context="代码库路径：~/project",
    toolsets=["file", "terminal"],  # 没有 "delegate"！
                                    # 子 Agent 不能创建更多子 Agent
)

This is an intentional safeguard against subagents spawning endlessly and exhausting resources.

6.3 Communication between main agent and subagent

主 Agent                          子 Agent
    │                                  │
    │  ① delegate_task(goal, context)  │
    │ ─────────────────────────────────▶
    │                                  │
    │                           ② 构建自己的消息
    │                           ③ AI 循环（可调用工具）
    │                                  │
    │                           ④ 返回最终回复
    │ ◀─────────────────────────────────
    │                                  │
    │  ⑤ 主 Agent 把子 Agent 的回复   │
    │     注入自己的 messages[]        │
    │                                  │
    ▼  ⑥ 主 Agent 继续工作            │

7. Resource isolation and safety

7.1 Why isolate?

场景：
  子 Agent A 执行了一个有风险的命令：
  rm -rf /important/project
  
  如果没有隔离，这个命令会删除主 Agent 工作目录的文件！

解决方案：
  每个子 Agent 运行在独立的 task_id 下
  → 文件操作被限制在 task_id 对应的目录
  → 危险的 rm -rf 不会影响到主目录

7.2 Process-level isolation

# 子 Agent 的创建可以指定不同的运行环境

subagent = AIAgent(
    session_id=f"{session_id}:child:{index}",
    
    # 指定运行环境
    backend="docker",           # 在 Docker 容器里运行
    docker_image="hermes/agent", # 使用隔离的 Docker 镜像
    # 不指定则默认在本地运行
    
    enabled_toolsets=["terminal", "file", "web"],
)

7.3 Tool-level safety

# 子 Agent 不能调用的工具（在注册时标记）

AGENT_LOOP_TOOLS = {
    "delegate_task",     # 子 Agent 不能创建更多子 Agent
    "memory_manage",    # 子 Agent 不能修改主人记忆
    "skill_manage",     # 子 Agent 不能修改 Skills
    "cronjob_manage",   # 子 Agent 不能创建定时任务
}

# 在 handle_function_call 中拦截
if function_name in _AGENT_LOOP_TOOLS:
    return json.dumps({
        "error": f"{function_name} must be handled by the agent loop"
    })

  → 三个子 Agent 同时开始研究
