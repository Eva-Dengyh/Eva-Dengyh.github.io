GitHub Weekly: Better Coding Habits, Persistent Memory, and Agent Teams

Eva·2026.04.19·10 min read

 

Writing code with AI is nothing new, but most people's experience stalls at the same stage: it works reasonably well, yet a few things remain maddening. Ask it to change one function and it casually refactors half a module. Spend twenty minutes explaining the project yesterday, and you must start over in today's new session. Try running several tasks at once, and the Agents have no idea what the others are doing. The problem is not insufficient model intelligence; the tooling has not caught up. Three GitHub projects this week are worth watching and may address these issues.

1. andrej-karpathy-skills

Repository: multica-ai/andrej-karpathy-skills
Stars: 58.6k ⭐ | Forks: 5.1k

Background

This project starts with a question:Why does AI keep making the same coding mistakes?

Andrej Karpathy—OpenAI co-founder and former Tesla AI director—has systematically observed and summarized common LLM shortcomings in coding tasks. This project turns his insights into a CLAUDE.md configuration file that attaches directly to Claude Code, using rules to constrain AI behavior.

The project itself is remarkably restrained: its core is just one file. Yet it has nearly 60,000 GitHub stars, suggesting these “bad AI habits” are a shared pain point for almost all heavy users.

Four Core Principles

1. Think Before Coding

AI's default behavior is to act as soon as it receives instructions. When uncertain, it tends to make assumptions instead of asking questions. This principle requires it to state uncertainties explicitly and ask questions before coding, rather than silently treating assumptions as confirmed. Silence often costs much more than one extra question.

2. Simplicity First

AI has a clear tendency to overengineer: turning a 50-line solution into 200 lines, or introducing design patterns where a simple function would suffice. This principle requires only the minimum code needed for the current problem and explicitly says that code must be rewritten if it can be simplified.

3. Surgical Changes

Give AI a small task and it often “optimizes” surrounding code, changes the style, or even refactors unrelated modules. This is dangerous in collaborative projects because you do not know what changed. The principle requires changes only to code directly related to the request, strict adherence to existing style, and no unrelated modifications.

4. Goal-Driven Execution

AI sometimes “completes the task” without solving the problem. This principle requires translating the task into verifiable success criteria before execution, then continuing until the goal is actually achieved rather than treating runnable code as the finish line.

How to Use It

The project supports three integration methods:

  • Plugin Marketplace (recommended): Install the karpathy-skills plugin in one step through Claude Code's plugin marketplace
  • Per-project mode: Download CLAUDE.md into the project root; it applies only to that project
  • Global mode: Place it in Claude Code IDE's rules directory (.Claude Code/rules/karpathy-guidelines.mdc), applying it to all projects

The repository also includes EXAMPLES.md (practical examples) and README.zh.md (a Chinese version).

Why It Matters

This project represents more than a configuration file. It expresses a view:The ceiling of AI coding tools depends not only on model capabilities, but also on how we constrain and guide their behavior. Sixty thousand stars are users voting for that view.

2. claude-mem

Repository: thedotmack/claude-mem
Stars: 62.6k ⭐ | Forks: 5.2 k

Background

Claude Code sessions are stateless. Each new session knows nothing about your project: architecture decisions, past pitfalls, and agreed coding conventions all reset to zero.

claude-mem was created by developer Alex Newman (@thedotmack) to add a persistent cross-session memory system to Claude Code. It does not modify the model or rely on external AI services; hooks locally capture, compress, and store session content, then intelligently inject relevant context into the next session.

How It Works

Five lifecycle hooks drive the system, covering the full session lifecycle:

SessionStart → UserPromptSubmit → PostToolUse → Stop → SessionEnd

After each hook fires, relevant content is sent to a local Worker HTTP API on port 37777, semantically processed, and written into two storage layers:

  • SQLite (with FTS5): Fast, precise full-text retrieval
  • Chroma vector database: Semantic retrieval that understands fuzzy queries

At the start of the next session, the system automatically retrieves relevant memories from both layers and injects them into the context.

Core Features

Progressive Disclosure (Three-Level Retrieval, About 10× Token Savings)

This is one of claude-mem's most important designs. Memory retrieval has three levels, accessed on demand to avoid overflowing the context by loading too much history at once:

  1. 1. search — Compact index summaries, about 50–100 tokens, quickly locate relevant memories
  2. 2. timeline — Timeline context for understanding event order
  3. 3. get_observations — Retrieve full details by ID, about 500–1,000 tokens

Natural-Language Skill Search

Through the mem-search command, you can query past coding experience in natural language, such as “How did we handle authentication last time?”

Real-Time Web UI

At http://localhost:37777, a visual memory-stream interface lets you see what the AI is remembering in real time and manage memory entries manually.

Privacy Controls

Content marked with <private> tags is automatically excluded from the memory store. This is useful for sensitive content such as API keys and personal information.

Citation System

Every memory has a unique observation ID for tracing its source, ensuring recalled content can be verified and tracked back.

Compatibility and Installation

Besides Claude Code, claude-mem supports mainstream Agent tools such as Gemini CLI and OpenCode through the MCP (Model Context Protocol) tool protocol.

Installation options include npm, a bash script, and one-click Plugin Marketplace installation. It requires Node.js 18+; the Bun runtime is configured automatically during installation, and SQLite 3 is bundled, requiring no separate installation.

The project provides a complete documentation site at docs.claude-mem.ai and a Discord community.

Limitations and Considerations

The project currently has 142 open Issues, indicating active iteration; some edge cases may still be unstable.ragtime uses the PolyForm Noncommercial 1.0.0 license, so commercial use must respect its licensing restrictions.

3. multica

Repository: multica-ai/multica
Stars: 16.3k ⭐ | Forks: 2k

Background

multica's ambition goes further than the first two projects. It is building an AI Agent collaboration platform where multiple coding Agents cooperate like actual team members, rather than improving one AI's behavior.

The project's slogan is: “Your next 10 hires won't be human.”

This is more than a gimmick. multica's core idea is that AI Agents should appear on project boards, join conversations, create Issues, and report blockers like real remote colleagues, rather than merely wait for commands in a terminal.

Core Features

Agents as Team Members

Each Agent has an independent member profile in multica. Agents can:

  • View and claim tasks on project boards
  • Join task discussions, ask questions, and report progress
  • Automatically create Issues when blocked
  • Push execution progress in real time through WebSocket

This differs fundamentally from traditional AI tools' question-and-answer interaction: the Agent is an active participant rather than a passive responder.

Autonomous Execution Across the Full Lifecycle

From assignment to completion, the Agent independently understands requirements, breaks down steps, writes code, runs validation, and submits results. Users assign tasks on the board and can leave the entire process to the Agent.

Skill Reuse (Skill Compounding)

Solutions accumulated during task execution can become shareable “skills” reused by other Agents or projects. This builds knowledge assets, addressing the problem of AI capabilities disappearing after use rather than accumulating.

Unified Runtime Management

The multica CLI automatically detects and centrally manages local daemons and cloud compute resources, so users need not manually distinguish where tasks execute. Multiple isolated workspaces support team collaboration.

Technical Architecture

LayerTechnology
FrontendNext.js 16 (App Router), TypeScript (53.4%)
BackendGo + Chi router + sqlc (43%)
Real-time communicationgorilla/websocket
DatabasePostgreSQL 17 + pgvector

Go handles highly concurrent task scheduling and Agent communication, Next.js handles the web interface, and pgvector provides vector retrieval for Agent skills. The architecture emphasizes performance and scalability for running multiple Agents simultaneously.

Supported Agents

As a platform layer, multica supports mainstream coding Agents including Claude Code, Codex, OpenClaw, OpenCode, Hermes, Gemini, and Pi. Users can mix different Agents on the same board, assigning tasks to the best-suited executor.

Deployment Options

  • macOS/Linux: Install the CLI through Homebrew (brew install multica-ai/tap/multica)
  • Windows: Install through a PowerShell script
  • Self-hosted: Complete Docker deployment; see SELF_HOSTING.md
  • Cloud service: Official hosted instance at multica.ai/app

Project Status

The latest version, v0.2.6, was released on April 18, 2026. At publication, the project remains under active development, with 43 releases and 109 open PRs. With 16,000+ stars and 54 contributors, it is still in an early stage of rapid growth, with stability and completeness continuing to improve.

Summary

The three projects pursue different directions and serve somewhat different audiences. andrej-karpathy-skills has almost no entry barrier: add one file and you can feel the difference that day; it suits anyone using Claude Code. claude-mem grows more valuable over time: the longer a project runs, the more useful its accumulated context becomes; it suits developers working on long-term projects. multica is the heaviest of the three and is still iterating rapidly. Its features are already usable, but setup takes some effort, making it best suited to teams serious about multi-Agent workflows.
