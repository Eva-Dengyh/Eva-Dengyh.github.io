1. What Problem Does Memory Solve?

1.1 The Fatal Flaw of Standard Agents

Most AI agents have a fatal problem: they remember nothing once a conversation ends.

第 1 天：
用户：我是 Eva，在AA科技工作
Hermes：好的 Eva，我记住了！
第 1 天结束，关闭 Hermes

第 2 天：
用户：我叫什么名字？
Hermes：抱歉，我不知道...
用户：我在哪工作？
Hermes：抱歉，我也不记得了...

This happens because:

  • AI models have limited context windows
  • Conversation history is truncated when it becomes too long
  • Information is completely lost after a session ends

1.2 Hermes's Solution

Hermes has a persistent memory system that stores important information on disk:

第 1 天：                               第 2 天：
用户：我是 Eva，在AA科技工作           │
      │                                  │
      ▼ 记忆工具提取并存储               ▼ 从磁盘读取
~/.hermes/memory/                    ~/.hermes/memory/
└── user_eva.md                       └── user_eva.md
     - name: Eva                            - name: Eva
     - company: AA科技                     - company: AA科技
                                         │
                                         ▼ AIAgent 自动加载
用户：我叫什么名字？                      │
      │ ◀───────────────────────────── AI 知道 Eva 叫什么

2.2 Types of Memory

Hermes stores several types of memory:

USER.md        → 用户个人信息（名字、职业、偏好）
MEMORY.md      → 事实性记忆（重要事件、项目信息）
preferences.md → 用户偏好（编程语言、咖啡口味）
skills/*.md    → 经验性记忆（Skills，见下一节）

2.3 Memory Storage Format

Memories are stored as Markdown files in the ~/.hermes/memory/ directory:

# user_eva.md

**Name:** Eva
**Company:** AA科技
**Role:** AI 全栈开发工程师
**Timezone:** Asia/Shanghai

**Preferences:**
- Language: Python
- Editor: Cursor
- Coffee: 不喜欢美式咖啡

**Personal:**
- 喜欢吃麻辣火锅
- 常用编程语言：Python

3. How Memories Are Extracted and Stored

3.1 Two Ways to Remember

主动记忆：用户明确说"记住 X"
  用户："帮我记住，我喜欢用 Cursor 编辑器"
    → Hermes 调用 memory_tool 存储

被动记忆：Hermes 自动提取
  用户说了一段话，Hermes 自动判断"这值得记住"
    → 自动触发存储逻辑

3.2 Implementing memory_tool

tools/memory_tool.py provides two core operations:

def memory_tool(action: str, target: str, content: str = None, old_text: str = None):

    action: "add" | "replace" | "remove"

    content: 新内容（add/replace 时）
    old_text: 要替换的旧文本（replace/remove 时）
    """
    
    if action == "add":
        # 新增记忆
        filepath = get_memory_path(target)
        with open(filepath, "a") as f:

        return json.dumps({"success": True, "message": "记忆已更新"})

3.3 Deciding What to Remember

Hermes does not remember everything. It intelligently decides what is worth retaining:

# memory_manager.py

def should_remember(text: str) -> bool:
    """
    判断用户说的这段话是否值得存储为持久记忆。
    """
    # 提取潜在的事实
    facts = extract_facts(text)  # 命名实体识别
    
    # 以下情况值得记住：
    # 1. 包含个人信息（名字、职业、地点）
    # 2. 用户明确说"记住..."
    # 3. 包含偏好（喜欢/讨厌...）
    # 4. 包含重要约定或计划
    
    return len(facts) >= 2  # 至少包含 2 个实体才值得记住

4. How Memories Are Recalled

4.1 When Recall Happens

Memories are loaded into AIAgent's system prompt at the start of every conversation:

Session 启动
    │
    ▼
memory_manager 读取 ~/.hermes/memory/
    │
    ▼
构建"用户信息块"，注入系统提示词
    │
    ▼
AIAgent 在回答时自动知道这些信息

4.2 Code for Recall and Injection

# agent/memory_manager.py

def build_memory_context_block(user_id: str) -> str:
    """
    读取用户记忆，构建注入给 AIAgent 的文本块。
    """
    blocks = []
    
    # 读取用户信息
    user_file = get_memory_path("user")
    if os.path.exists(user_file):
        blocks.append(f"## User Information\n{read_file(user_file)}")
    
    # 读取一般记忆
    memory_file = get_memory_path("memory")
    if os.path.exists(memory_file):
        blocks.append(f"## Memorable Facts\n{read_file(memory_file)}")
    
    # 读取偏好
    prefs_file = get_memory_path("preferences")
    if os.path.exists(prefs_file):
        blocks.append(f"## User Preferences\n{read_file(prefs_file)}")
    
    return "\n\n".join(blocks)

5. Skills: Beyond Ordinary Memory

5.1 What Are Skills?

Skills = experiential memory.

Ordinary memory stores facts ("Eva likes Python"), while Skills store experience ("how I solved a Python bug Eva encountered").

Memory（事实记忆）:
  "用户叫 Eva"
  "用户在AA科技工作"
  "用户喜欢吃麻辣火锅"

Skills（经验记忆）:
  "当用户让我调试 Python 时：
   1. 先让用户提供完整错误信息
   2. 检查是否是 ImportError / SyntaxError / IndexError
   3. 按类型排查..."

  "当用户让我帮忙 code review 时：
   1. 先了解项目结构
   2. 重点检查安全性（SQL注入、XSS等）
   3. 检查代码可读性和命名规范..."

5.2 The Core Value of Skills

没有 Skills：
第 1 次：用户让我做 X → 我摸索着做，花了 30 分钟
第 2 次：用户让我做 X → 我又重新摸索，又花了 30 分钟
第 N 次：每次都要重新摸索

有 Skills：
第 1 次：用户让我做 X → 我摸索着做，成功
       → 我把经验存成 skill_python_debug.md
第 2 次：用户让我做 X → 找到 skill_python_debug.md
       → 按步骤做，花了 5 分钟
第 N 次：Skills 越来越完善，做得越来越快

5.3 Skills vs. Ordinary Tools

DimensionOrdinary ToolsSkills
CreatorDevelopers write codeAgents extract them from their own experience
ContentPrecise operational stepsHeuristic guidance from experience
TriggerCalled directly by the AI modelThe model decides whether to load them based on the situation
GranularityPrecise down to function parametersCoarse-grained and organized by scenario

6. Skill Storage Format

6.1 Skills Directory Structure

~/.hermes/skills/
├── python-debug/
│   └── SKILL.md          ← 一个 Skill
├── code-review/
│   └── SKILL.md
├── research/
│   └── SKILL.md
└── ...

6.2 SKILL.md Format

Each Skill is a Markdown file containing a fixed set of sections:

# python-debug

## name
python-debug

## description
当用户描述 Python 错误、异常、或要求"帮我调试"时触发。
提供系统化的 Python 调试方法。

## trigger
用户说了以下关键词之一：
- "报错了"
- "出错了"
- "帮我看看"
- "调试"
- "traceback"
- "Exception"
- Python 相关的错误信息

## steps
1. **收集信息**
   - 让用户提供完整的错误信息（traceback）
   - 如果没有，提供重现步骤
   
2. **分析错误类型**
   - SyntaxError：检查拼写、缩进、括号匹配
   - ImportError：检查包是否安装、路径是否正确
   - IndexError / KeyError：检查边界和键名
   - TypeError：检查变量类型是否匹配
   - 自定义异常：追踪异常来源

3. **定位问题**
   - 从 traceback 最底部往上读
   - 找到第一个 "File" 行，那通常是问题所在
   - 注意 "in" 后面的函数名

4. **修复与验证**
   - 给出修复方案
   - 建议用户验证修复是否成功
   - 如果失败，继续分析

## notes
- 不要在看到完整 traceback 前就猜测原因
- Python 对缩进敏感，Tab 和空格混用是常见错误
- 虚拟环境没激活也会导致 ImportError

## examples
用户："Python 报错 ImportError: No module named 'requests'"
助手：
1. 检查是否安装了 requests：pip show requests
2. 如果没有，安装它：pip install requests
3. 如果安装了但还是报错，检查是否在正确的虚拟环境中

---
Created: 2025-03-20
Updated: 2025-03-24
Times used: 12

7. Retrieving and Invoking Skills

7.1 When Are Skills Retrieved?

Skills are retrieved before every AIAgent decision:

用户消息进来
    │
    ▼
检索相关 Skills（基于关键词匹配）
    │
    ▼
找到相关 Skill → 把它的内容注入系统提示词
    │
    ▼
AIAgent 带着 Skill 指导继续工作

7.2 Retrieval Algorithm

# agent/skill_utils.py

def retrieve_skills(query: str, top_k: int = 3) -> List[Skill]:
    """
    根据用户查询检索最相关的 Skills。
    """
    # 1. 关键词匹配
    query_words = set(query.lower().split())
    
    scored = []
    for skill_path in list_skills():
        skill = load_skill(skill_path)
        
        # 计算关键词重叠度
        trigger_words = set(skill.trigger.lower().split())
        overlap = len(query_words & trigger_words)
        
        # 计算 TF-IDF 相似度（简化版）
        tfidf_score = compute_tfidf(query, skill.description)
        
        # 综合得分
        final_score = overlap * 2 + tfidf_score
        scored.append((final_score, skill))
    
    # 2. 按得分排序
    scored.sort(reverse=True)
    
    # 3. 返回 Top K
    return [skill for _, skill in scored[:top_k]]

7.3 The Result of Skill Injection

用户："我的 Python 脚本报错了，能帮我看看吗？"

系统提示词中注入：
---
## Active Skills

### [python-debug] (relevance: 0.95)
当用户描述 Python 错误时触发。

Steps:
1. 收集完整错误信息
2. 分析错误类型（SyntaxError/ImportError/IndexError/TypeError）
3. 从 traceback 底部往上看，找到第一个 File 行
4. 给出修复方案

Notes:
- 不要猜测，要先看完整 traceback
- 检查缩进、虚拟环境、包安装
---

AIAgent 看到用户"报错"，自动加载了 python-debug Skill，
按照 Skill 里的步骤引导用户提供信息，而不是乱猜。

8. How Skills Evolve

8.1 When Evolution Happens

Hermes decides whether a new Skill is worth creating after a task completes:

复杂任务完成（耗时 > 5 分钟，或工具调用 > 10 次）
    │
    ▼
Hermes 问自己：
"这次任务有什么值得以后复用的经验吗？"
    │
    ▼
如果有价值：
  → Hermes 自动创建/更新对应的 Skill
  → 增加使用次数计数
  → 更新 Last Updated 时间

8.2 Code for Automatic Evolution

# tools/skill_manager_tool.py

async def check_and_evolve_skills(
    task_description: str,
    conversation_history: List[dict],
    outcome: str,
):
    """
    检查是否需要从这次任务中提取新经验。
    """
    # 1. 判断任务复杂度
    if len(conversation_history) < 5:
        return  # 任务太简单，不需要记录
    
    # 2. 判断是否有成功经验
    if "error" in outcome.lower() or "fail" in outcome.lower():
        return  # 失败的任务不提取
    
    # 3. 让 AI 自己判断是否值得创建 Skill
    should_create = await ask_llm(
        f"""
        用户刚才完成了这个任务：
        {task_description}
        
        这次任务的成功经验是否值得以后复用？
        如果值得，应该怎么总结成步骤？
        """
    )
    
    if should_create["worth_saving"]:
        # 4. 创建或更新 Skill
        skill = build_skill_from_conversation(
            task_description,
            should_create["steps"],
            should_create["trigger_keywords"],
        )
        save_skill(skill)

8.3 A Skill's Lifecycle

创建（Create）
    │
    ▼
首次使用（First Use）
    │
    ▼
重复使用（Repeated Use）
    │
    ▼
遇到问题 → 修正 Skill（Refine）
    │
    ▼
越来越完善 → 成为"专家级"Skill

9. Memory vs. Skills: Comparison

DimensionMemorySkills
Stored contentFacts, such as Eva liking hot potExperience, such as how to debug Python
CreationThe user says "remember," or information is extracted automaticallyThe agent automatically distills experience from tasks
PurposeHelp AI know who the user isHelp AI perform better on similar problems
Update frequencyAs neededPotentially after every relevant task
File format~/.hermes/memory/*.md~/.hermes/skills/*/SKILL.md
Recall methodInjected at the start of every conversationRetrieved on demand and injected when matched
AnalogyA person's memoryA person's skills handbook or experience notes
